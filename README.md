# monitor-input

Switch a monitor's input source (DisplayPort / HDMI 1 / HDMI 2) from a tray icon or a global hotkey, on Windows and macOS.

## How it works

Monitors accept commands over **DDC/CI**, an I2C channel inside the DP/HDMI cable (address `0x37`).
Input selection is the VESA MCCS VCP code **`0x60` (Input Source)**.
ASUS DisplayWidget does exactly the same thing: `DisplayWidget.exe` calls `SetVCPFeature` from `dxva2.dll`,
and the input values in its UI (`ui/html/main.html`) are the standard MCCS ones:

| Input         | VCP 0x60 value |
|---------------|----------------|
| DisplayPort   | `0x0F` (15)    |
| DisplayPort 2 | `0x10` (16)    |
| HDMI 1        | `0x11` (17)    |
| HDMI 2        | `0x12` (18)    |
| USB-C         | `0x13` (19)    |

Run `monitor-input list` to see which values your monitor advertises.

Wire format of a write: `51 84 03 60 00 <value> <checksum>`, checksum = XOR of all bytes and `0x6E`.

## Windows

```
windows\install.cmd
```

Builds, copies the binaries to `%LOCALAPPDATA%\MonitorInput`, enables start with Windows and launches the tray app.
Re-run it after code changes: the running copy is stopped and replaced, your hotkeys are kept.
`windows\uninstall.cmd` removes everything (including the hotkey config).

`windows\build.cmd` only builds in place. It uses the C# compiler that ships with Windows (.NET Framework 4.x), nothing to install. Produces:

* `monitor-input.exe` - CLI: `list`, `get`, `set hdmi1`, `set dp,hdmi1` (cycles between the listed inputs)
* `monitor-input-tray.exe` - tray app:
  * left click on the icon opens a small window with a button per supported input
  * global hotkeys from `monitor-input.ini` (created next to the exe on first run, i.e. `%LOCALAPPDATA%\MonitorInput` when installed):
    ```
    monitor = auto
    Ctrl+Alt+1 = dp
    Ctrl+Alt+2 = hdmi1
    Ctrl+Alt+3 = hdmi2
    ```
  * "Sleep display" button in the window (`SC_MONITORPOWER`, no DDC needed)
  * right click menu: Choose input, Sleep display, the hotkey actions, Start with Windows, Edit hotkeys, Reload hotkeys, Exit

## macOS (Apple Silicon)

```
mac/install.sh
```

Needs the Xcode Command Line Tools (`xcode-select --install`).
Builds `MonitorInput.app`, copies it to `~/Applications`, enables launch at login, links the CLI as
`~/bin/monitor-input` and starts the app. Re-run it after code changes: the running copy is replaced, your hotkeys are kept.
`mac/uninstall.sh` removes the app, the login item and the link (the hotkey config is kept).

`mac/build.sh` only builds in place. Produces:

* `monitor-input` - CLI: `list` (current input, model, advertised inputs), `get`, `set hdmi1`,
  `set dp,hdmi1` (cycles between the listed inputs), `-m <index|name>` to pick a monitor
* `MonitorInput.app` - menu bar app (no Dock icon), the same binary:
  * left click on the icon opens a popover with a button per supported input, the current one marked
  * global hotkeys from `~/.config/monitor-input.conf` (created on first run):
    ```
    monitor = auto
    ctrl+opt+1 = dp
    ctrl+opt+2 = hdmi1
    ctrl+opt+3 = hdmi2
    ```
    Modifiers: `cmd`, `ctrl`, `opt`, `shift`. Registered with Carbon `RegisterEventHotKey`, so no Accessibility permission is needed.
  * "Sleep display" button in the popover (`pmset displaysleepnow`, no DDC needed)
  * right click menu: Choose input, Sleep display, the hotkey actions, Launch at login, Edit hotkeys, Reload hotkeys, Quit

Apple Silicon has no public DDC API, so this uses the private `IOAVServiceWriteI2C` / `IOAVServiceReadI2C`
(same approach as MonitorControl, BetterDisplay and m1ddc).

The built-in HDMI port of the M1 Mac mini goes through an internal DP -> HDMI converter. At the usual chip address
`0x37` the converter answers DDC/CI itself (empty "null message" replies, writes dropped); at `0xB7` (bit 7 set)
the request reaches the monitor. The app tries `0x37` first and switches to `0xB7` when it gets a null message,
so both the built-in HDMI and USB-C/Thunderbolt adapters work.

The app icon is generated by `mac/icon/make-icon.swift` (same design as the Windows icon); the menu bar icon is drawn in code.

## Limitations

* Most monitors only accept DDC/CI from the **active** input, so the computer currently on screen
  is the one that switches away: Windows -> `Ctrl+Alt+2` -> Mac, Mac -> `Ctrl+Opt+1` -> Windows.
* DDC/CI must be enabled in the monitor OSD (ASUS: System Setup -> DDC/CI).
* Mac: tested on an M1 Mac mini (built-in HDMI and a USB-C -> HDMI adapter). Some adapters and docks do not pass DDC at all.
* Intel Macs are not supported (different API, IOFramebuffer); use `ddcctl` there.
